# Typed RPC hot-path stage — approved three-part scope

User approved: (1) void notifications have no application success replies/waiters/timeout CTS; (2) generated strongly typed serializers/receivers, numeric method IDs and schema fingerprint validation; (3) a single leased message buffer and slice readers through transport. Task/Task<T> retain request/reply semantics and regression coverage. Host dynamic method-catalog distribution is explicitly deferred; never imply downloaded metadata supplies executable code.

## Acceptance, not just renaming

- Normal woven calls (concrete and interface) must not enter object[]/boxing/MethodInfo.Invoke for parameter encoding or receive invocation. Generate direct typed entrypoints/receivers for supported declarations, not a generated helper which then calls the old reflection bridge. Receiver delegates are registered once, not created per call.
- Prefer existing Cecil build-time generation if that preserves arbitrary ordinary method bodies/inheritance/private receive bodies without imposing partial-class authoring. SourceGenerator is permitted; neither path may emit IL dynamically during gameplay. State clearly which build-time generator is used. This stage does not require rewriting supported user-facing methods into a new separate send API.
- Numeric method ID collisions are detected. Validate a generated schema fingerprint (including parameter schema/order and return/delivery/route) before invocation; equal short IDs do not imply compatibility. Names are cold metadata, not hot payload routing keys. Per-room target/session/peer lookup is isolated and authenticated. Generated wire header should be a readonly value type with numeric identities; cold control/snapshot and existing explicit reflection-oriented proxy APIs may retain documented compatibility machinery, not secretly be called by the generated hot path.
- void is an actual one-way notification: zero result waiters, zero fanout ACK tables/timers, no success reply. Local validation/send faults surface locally, remote handler faults are receiver diagnostics. No fake promise of remote completion. Task and Task<T> still await remote completion/result and preserve remote errors/timeout/cancellation.
- Parameters serialize directly into one pooled message writer; receive handlers read bounded slices directly. No per-parameter byte[][], CopyOwned/ToArray or object[] in the normal generated path. Sender data freezes synchronously before the wrapper returns. Decoder argument lifetimes must not outlive borrowed bytes; arrays/DTOs requiring owned application values may still allocate and must be accounted honestly.
- Frame ownership must survive asynchronous transport/fanout, exceptions, room disposal and reentrancy. Pool implementations must not allocate a ConcurrentStack node per return. Bound in-flight calls and queued bytes. Local Host execution should avoid serializing merely to decode for itself when a safe typed route is available.
- Authorization, ready barriers, original sender relay, tombstones/state, Host/Client exclusivity, nested calls and async RpcCallContext behavior remain correct. Cache/cold-register metadata; don't create AuthorizationRequest/Member/Context objects per scalar notification if avoidable. If preserving legacy Current semantics conflicts with zero-GC, provide a value-context accessor for the generated path and document remaining compatibility allocations rather than reuse an escapable mutable singleton.

## Transport seam (Astra-owned shared interface)

`Src/Runtime/RoomMemoryContracts.cs`: IRoomMemoryWire.MemoryReceived and ValueTask SendMemoryAsync.

Runtime subscribes to MemoryReceived INSTEAD OF the legacy byte[] event where available. Callback memory is borrowed; decode synchronously or copy/retain one owned frame before returning. SendMemoryAsync borrows caller memory until completed/faulted; even completed ValueTasks must be consumed. Existing IRoomWire API stays for legacy/control compatibility. Add this interface to production Direct/Relay wires and sample runtime wrappers. No duplicate delivery. An old byte[]-only test/user wire may require an explicitly documented copying adapter; it is not the performance path.

Direct DMTP gameplay forwards e.DmtpMessage.Memory without ToArray when using the memory event. Relay must copy borrowed incoming data once into pooled owned memory before its asynchronous mailbox, then parse slices rather than allocate per blob. Preserve bounded ordered queues. On close, never return a send buffer while the underlying DMTP Task still references it—even if the caller has already been notified of disconnect. Cold admission/control string parsing may remain separately bounded.

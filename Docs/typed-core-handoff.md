# Typed RPC core handoff (Cecil / binary v4)

## Integration API and versions

- **Generator is the existing Mono.Cecil build-time weaver**, not a Roslyn Source Generator. It keeps ordinary `[Rpc]` implementation bodies, moves each body into `__bitkit_body_*`, and emits a typed wrapper plus a static `__bitkit_recv_*` receiver per **Reliable and Unreliable** declaration. Normal woven concrete and interface calls use `DispatchBridge.BeginTyped`, `TypedRpcWriter.Write<T>`, `FinishVoid` / `FinishTask<T>`; receiver delegates are registered **once at Bind**. No runtime IL compilation. The build-time `WovenTypedRpcAttribute` carries the numeric method ID and schema fingerprint. MemoryPack's separate source generator is still required for reference DTOs marked `[MemoryPackable]`.
- **Hot application calls (Reliable memory lane and Unreliable UDP lane):** magic `B6`, version **4**, readonly `TypedRpcHeader` (**88 bytes**): byte kind (`1` reliable notification, `2` reliable Task request, `3` unreliable notification), byte route, two UInt64 room-scope hash parts, two UInt64 target hash parts, UInt64 sender and destination peer IDs, UInt64 method ID, UInt64 schema fingerprint, 16-byte request GUID and Int32 payload length. Arguments follow as bounded, length-prefixed MemoryPack slices. No routing strings, CLR names, `object[]`, per-parameter `byte[][]` or `MethodInfo.Invoke` in the generated wrapper/receiver. The scope hash uses **strict UTF-8**; the target hash uses three **length-prefixed strict UTF-8** fields, not NUL separators (`TargetKey` permits embedded NUL). Both use 128-bit truncated SHA-256 computed on bind; numeric peer IDs and method IDs use deterministic 64-bit FNV-1a. Bind/directory checks detect differing string identities assigned the same numeric key; method ID collision is a weave error and fingerprint/route/**actual arrival lane** are checked at receiver before invoking the body. Room identity remains additionally bound to the authenticated wire/session. Scope/target hash encoding and schema-fingerprint changes require a **full rebuild of all room peers**, although the byte header version remains 4.
- **Cold reliable controls, SyncVar, membership, tombstones, explicit reflection `CreateProxy`/`CallAsync` and Task replies:** existing bounded binary **v3 / B5**, not JSON. Generated Task requests start on v4, use typed argument reads/direct body invocation and preserve pending reply/timeout/cancellation behavior; their binary replies remain v3. **Normal woven Unreliable void calls use B6 kind 3 on `IRoomDatagrams`**, not the old B4 format. B4/v2 remains only for explicitly reflection-oriented Unreliable proxy compatibility and bounded old-frame reception; never a fallback when the v4 UDP lane is unavailable. `MeasureUnreliableCall(TargetKey, MethodInfo, object?[])` caches validated delivery/route, parameter types, target position and typed marker **per runtime** (maximum 1,024 method schemas; cleared at Dispose). The woven B6 measurement serializes with the same MemoryPack value writer and 64 KiB candidate cap, but uses a default **fixed-width 88-byte header**: method/peer/target hash values cannot affect length, so no `Packet`, `MethodId` string or SHA hash is recomputed per candidate. It still validates target/argument metadata and does not estimate a pose formula. B4 explicit compatibility measurement retains its old codec. The returned size is the actual encoded UDP payload for byte-budget batching (900 B advertised in the sample wire). Caller-supplied `object?[]`/boxed arguments remain part of this reflection-oriented measurement API, not the woven send path. Participants must use compatible room code. Dynamic Host method-catalog distribution is **deferred**—a remote-only Host relay policy gets a `#<numeric-method-id>` method label rather than downloading executable metadata. That policy must authorize explicitly; recipient fingerprint validation still applies.
- `IRoomMemoryWire` is already defined in `RoomMemoryContracts.cs`. `RpcRuntime` subscribes to **`MemoryReceived` instead of `Received`** if present; cold v3 controls take one owned copy from borrowed memory, while hot v4 readers finish decoding arguments before the callback returns. `SendMemoryAsync` borrows a pooled sender frame until its `ValueTask` finishes (including faults). No duplicate event delivery. A legacy `IRoomWire`-only wire remains supported with an explicit exact-length `byte[]` copy for typed sends; this is **not** the zero-allocation transport path. Arena/sample wrappers should forward the memory event and send method without recopying borrowed input. No TouchSocket/Arena source was changed here.

## Delivery and buffer ownership

- **Woven void is one-way** on both generated v4 lanes and cold proxy v3/B4. No application success reply, waiter, fanout ACK table or timeout timer. Host All executes its own body exactly once **directly with original typed arguments**, then sends one encoded pooled frame to recipients passing the ready/HoldBroadcasts barrier. Warm synchronous fanout iterates a cold-rebuilt immutable ready-peer snapshot plus stack bitset, with one reference-counted frame and no per-send recipient/task arrays; genuinely asynchronous sends need continuation/task state. Remote handler failures appear via the **receiver's `UnhandledDispatch`**, not as a sender success/failure receipt. Local validation errors throw; asynchronous send failures are local diagnostics.
- Woven Task and Task<T> keep completion, return values and error replies. Cancellation of an explicit reflection `CallAsync` stops waiting, not a remote business body. A local Host Task uses the typed receiver without a network self-send. `RpcCallContext.Current` continues to provide an escapable class/AsyncLocal view; generated **synchronous void** receivers also expose `RpcCallContext.TryGetValue(out RpcCallValueContext)` without constructing that class when only the value accessor is used. Each synchronous frame captures its **AsyncLocal parent reference**: the active value frame wins over exactly that parent; a nested async child installs a different AsyncLocal context which wins during its own continuations. Exiting nested calls or throwing restores the previous frame. Thread-static frames neither flow across awaits nor retain borrowed readers or pooled buffers. Generated Task/Task<T> uses the AsyncLocal class context across awaits. No mutable singleton is reused as a public context. `AuthorizationRequest` is now a readonly struct and client receiver authorization uses cached ready `RoomMember`; arbitrary user `Authorize` callbacks and `RpcCallContext.Current` materialization can still allocate. This API is source-compatible with existing `Func<AuthorizationRequest,bool>` callbacks, but binaries compiled against the previous class signature must be rebuilt.
- `TypedPacketBuffer` uses a bounded, thread-local `Stack<TypedPacketBuffer>` and a single `ArrayPool<byte>` rental per frame, **not a ConcurrentStack node per return**. Cecil wrappers `Dispose` in `finally` on serialization/body faults. When sending, the buffer is detached, shared read-only among fanout sends and returned by a thread-local pooled reference-counted fanout lease only after **all** borrowed reliable or UDP sends complete/fault—even after runtime disposal. Async/slow wires can retain at most **128 outstanding typed frames per runtime**; the 129th is rejected *before* the local Host All body executes (not sent/fallen back). Reliable packet size is limited to **1 MiB**, and typed Unreliable to the lane's advertised limit (900 B in sample); schema-specific limits are checked before MemoryPack allocates nested values. Pool retention of returned arrays is not an active lease. A noncooperative wire that never completes its send can retain those bounded rentals indefinitely; it cannot be returned safely earlier.

## Schema and fallback boundaries

- v4 fingerprint includes route, delivery, return type and ordered parameter/DTO member schema, not just a method name/hash. Enum fingerprints include their **underlying type plus member names/values**. Raw unmanaged-struct fingerprints include sequential layout, packing, class size, field order/type and available offsets; explicit/overlapping layouts are rejected by the weaver/runtime rather than ambiguously fingerprinted. Reliable generated DTOs require default generated object layout and **contiguous explicit `[MemoryPackOrder(0..N-1)]` on every serialized member**. Field/property mixing is sorted by those orders, not incomparable metadata-table tokens. Annotated unmanaged structs are raw fixed-size MemoryPack values. Custom formatters, union/polymorphic/cyclic, version-tolerant/custom layouts, callbacks, private Include and ignored members are unsupported; the weaver diagnoses unsupported declarations and runtime checks the same schemas. Reliable DTOs may contain supported nested arrays/strings; top-level SyncVars **cannot contain collections at any depth**. Unreliable's narrower flat-schema restrictions remain, with explicit member orders required on its generated reference DTOs so a v4 fingerprint is stable.
- Numeric-only v4 calls need matching woven/bound implementations on receivers. Interface-to-implementation aliases continue to invoke the same woven wrapper. Explicit reflection-oriented proxy calls remain cold v3 and may allocate; they are not secretly used by the normal woven path. Cold directory, state, fault strings and generated Task replies remain documented allocation sources. `MemoryPack` deserialization necessarily allocates owned strings, arrays and reference DTOs; a variable-length `ArraySegment<T>` is not a zero-GC receive type.

## Verification and allocation scope

`Tests/TypedHotTests.cs` and `Tests/UnreliableRuntimeTests.cs` exercise actual compiled woven scalar, fixed unmanaged struct and `ArraySegment<struct>` declarations over borrowing fake `IRoomMemoryWire` and fake `IRoomDatagrams`: no object-array/boxing/reflection-invoke IL in generated wrappers/receivers **on either lane**, equal interface/concrete behavior, Task<T> completion, no duplicate legacy event, fingerprint and actual-arrival-lane rejection before the body, **async-parent → sync-void → async-child context restoration across `Task.Yield` and nested exceptions**, 8-way concurrent calls, delayed/faulted/disposed send ownership and an actual 128-send backlog. Core tests distinguish two different `TargetKey`s containing embedded NUL, check strict invalid Unicode, and show Cecil fingerprints change for struct packing and enum underlying type or values, with a mismatched frame rejected before the body. Normal woven reliable scalar `void` produced **0 measured bytes across 2,000 warmed sender-only calls and 0 across 2,000 warmed synchronous fake-memory-wire sender+receiver calls**, including a stateful Host authorization delegate, using `GC.GetAllocatedBytesForCurrentThread`. Warmed reliable fixed unmanaged scalar measured **0 B/1,000** remote, Host-local and two-peer Host All sends. Normal woven v4 UDP scalar and fixed struct measured **0 B/call** for 2,000 synchronous fake-datagram calls each; warmed two-peer Host All v4 UDP scalar also measured **0 B/call** across 1,000 calls. These are narrowly scoped synthetic measurements—not a promise of zero GC for variable DTOs, proxies, arrays decoded at receivers, real TouchSocket or asynchronous scheduling. The prior [`v4-gc-report.md`](v4-gc-report.md) records the **historical B4 JSON-to-MemoryPack prototype before typed v4**; do not treat its numeric measurements as the current hot path. The current repeatable opt-in typed UDP GC artifact is `Artifacts/GcRuns/v4-typed-unreliable-memorypack-20260927-215215.json`: one pose record 100 B; 30-pose batch 696 B; 30-pose receiver allocations about 625 B/send; eight-peer fanout about 4,993 B/send because each receiver owns its decoded array and the test uses reflection to invoke the woven wrapper. Packet rentals/pending replies were zero after each completed wave.

In the same warmed, **preboxed and reused one-element `ArraySegment<int>`** measurement fixture (`Warm_preboxed_measurement_reports_managed_allocation_and_returns_writer_lease`), the old per-candidate metadata/header/hash path allocated **15,961,208 B over 5,000 measurements = 3,192.24 B/call**. With the cached metadata and default fixed header, the measured current-thread delta is **0 B over 5,000 = 0.00 B/call** in that fixture. Both runs used the same `MeasureUnreliableCall` test, Release fake wire and preboxed argument array. This is not a general allocation guarantee for new argument boxes, variable DTOs, cold cache misses, or real game presentation. A separate regression compares measured size to the **actual** B6 UDP frame for segment windows with different offsets/counts, Unicode strings, short/Unicode Target peer IDs and 900-byte cap checks.
